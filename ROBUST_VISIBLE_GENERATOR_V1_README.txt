ROBUST VISIBLE GENERATOR V1

Goal
----
Train the generator itself so the entire candidate distribution has high
pre-execution information value about K, reducing reliance on a selector.

Scientific cleanliness
----------------------
1. Reward is predicted visible MI about K BEFORE candidate execution.
2. No actual candidate output / selected_roles / true K is used in the reward.
3. Generator training uses only observation-model TRAIN systems.
4. We branch from stage_10_cycle_01 because stage_10/cycle_02 candidates were
   generated by that exact policy. Therefore their stored old_logp is on-policy.
5. Held-out evaluation uses observation-model TEST systems only.
6. Evaluation first measures the generator distribution WITHOUT any MAS calls.

Robust lower-tail objective
---------------------------
Bottom quartile is penalized much more strongly than ordinary relative reward.
The target is not just a better best-of-8; it is better random / first / p10 /
p25 / worst-of-group quality.

Pipeline
--------
CPU label build
  -> existing GPU curriculum updater (one epoch, conservative LR/KL/retention)
  -> held-out GPU generation comparison:
       cycle01 branch
       existing final cycle02
       robust visible branch
  -> pre-execution visible-MI distribution metrics

The decisive fields are:
  robust_vs_existing_final.all_candidate_mean
  robust_vs_existing_final.all_candidate_p10
  robust_vs_existing_final.all_candidate_p25
  robust_vs_existing_final.random_candidate_expected_mean
  robust_vs_existing_final.candidate0_mean
  robust_vs_existing_final.mean_group_worst

A strong result lifts ALL of them, especially the lower tail.
